# Codex 开发任务：Word Detective Android

## 1. 项目目标

开发一款完整的 Android 原生英语侦探破案游戏，名称为 **Word Detective / 英语侦探**。

项目仓库：

`seki999/WordDetective_Android`

词汇数据来源：

`https://github.com/seki999/toeic-visual-vocabulary`

本项目是独立 Android 游戏，不能破坏或直接修改现有 TOEIC Web 项目。

目标是让用户通过学习 TOEIC 词汇、听英语对话、观察证据图片、回答问题和进行逻辑推理，完成一个个侦探案件。

不要仅开发简单的单词选择题 App，必须实现有完整起点、调查过程、线索收集、证据推理、结案结果的游戏流程。

## 2. 开发技术

- Kotlin
- Jetpack Compose + Material 3
- MVVM
- StateFlow / Kotlin Coroutines
- Room SQLite
- Kotlin Serialization
- Android TextToSpeech
- AndroidX Media3（在适用的音频播放场景）
- Android Gradle Plugin
- Gradle Kotlin DSL
- Python 3：用于词汇数据导入、内容验证和资源构建

选用适合当前环境的稳定兼容版本，避免使用互不兼容的依赖组合。

游戏主要支持 Android 手机，同时适配 Android 平板。

优先支持 Android 10 及以上系统。

禁止依赖外部服务器、云端 LLM、付费 API 或在线图片服务。

核心游戏必须可以在飞行模式下运行。

## 3. 原始词汇数据的导入

检查现有仓库：

`public/data/listXX.json`

以及：

`public/images/listXX/`

首先分析原始 JSON 的真实结构，禁止凭空假设字段。

当前已知词条包含：

- id
- word
- partOfSpeech
- ipa.uk / ipa.us
- meaning
- collocation.en / collocation.zh
- example.en / example.zh
- images
- tags
- notes
- sourceKey

注意：同一个英文单词可能对应多个独立 ID 和不同词义。

要求：

1. 使用 Python 建立导入工具。
2. 保留原始词条 ID。
3. 支持一个词条关联多个图片。
4. 保留英语及中文例句。
5. 保留所有独立词义。
6. 路径转换为 Android Assets 可使用的路径。
7. 验证引用的图片是否存在。
8. 验证 JSON 数据字段与类型。
9. 输入数据错误时显示明确错误报告。
10. 导入工具必须支持将来新增 List。
11. 不下载或生成无关音频文件。
12. 不允许运行时依赖原始 GitHub 仓库。

所有词汇与图片必须随 APK 一起分发。

## 4. 案件数据与游戏引擎

为案件设计独立 JSON Schema。

每个案件包含：

- caseId
- schemaVersion
- title
- description
- vocabularyListId
- requiredVocabularyIds
- characters
- scenes
- chapters
- dialogue
- questions
- clues
- deductions
- branches
- endings
- rewards
- unlockConditions

游戏引擎根据 JSON 驱动界面和逻辑。

不要在 Kotlin 代码中硬编码具体案件的台词和问题。

首版必须支持以下步骤类型：

- dialogue：英语剧情对话
- vocabulary：单词学习
- multiple_choice：四选一
- listening：英语听力
- image_choice：图片选择
- fill_blank：句子填空
- clue：收集证据
- deduction：线索组合推理
- ending：结案与成绩计算

每种步骤必须具有明确的输入、正确答案或完成条件，以及后继状态。

剧情状态机应支持：

- 顺序推进
- 条件解锁
- 失败重试
- 提示
- 分支选择
- 恢复游戏
- 重玩关卡
- 跳过已经阅读的内容

## 5. 首个案件：The Missing Sapphire

中文：消失的蓝宝石。

故事设定：

Meridian Museum 举行重要的珠宝展览。展览当天夜里，蓝宝石失踪。玩家扮演 Alex Chen，与警探 Emma Wilson 合作调查。

角色：

- Alex Chen：玩家侦探
- Emma Wilson：搭档
- Dr. Miller：法医专家
- Sophia Reed：重要证人
- Robert Hayes：博物馆经理
- David Brown：保安

设计 10 个关卡：

1. 接受案件
2. 勘查博物馆
3. 询问保安
4. 分析监控
5. 访问神秘证人
6. 分析物证
7. 整理矛盾证据
8. 嫌疑人对质
9. 最终审讯
10. 结案报告

要求剧情逻辑完整，案件有确定的真相和合理推理路径。

每个线索都必须有明确来源，不允许玩家通过尚未收集的信息回答题目。

最终推理题必须能够由之前获得的证据推出答案。

题目错误答案应具有合理迷惑性，但不能产生多个同样正确的选项。

所有场景必须使用连贯的英语剧情，并提供准确的简体中文翻译。

本案件的目标是覆盖 List01 的全部词条。

必须先统计实际词条数量与词义数量。

不要为了覆盖单词而制造不自然的对话。

难以融入主线的词语可以放进背景新闻、证人资料、文件、支线剧情或者结案附录。

最终生成词汇覆盖报告，列出：

- 总词条数
- 已覆盖词条数
- 未覆盖词条数
- 每个词条出现在哪些步骤中
- 哪些词条仍缺少图片

如果一次开发无法生成高质量完整剧情，必须先提供可运行的完整小型案件切片，并清楚列出尚未覆盖的内容。禁止使用无意义的重复台词或伪造完整性。

## 6. 用户界面

界面使用统一的 2D 侦探视觉风格：

- 深蓝和暖金色为主
- 半写实侦探主题
- 大幅场景插画
- 清晰的英语文字
- 对话人物头像
- 不使用密集的小字体
- 不采用儿童化卡通风格

页面至少包括：

1. 启动画面
2. 游戏主菜单
3. 案件选择
4. 案件地图
5. 剧情对话
6. 单词学习
7. 调查现场
8. 四选一
9. 听力挑战
10. 推理挑战
11. 证物背包
12. 结案评价
13. 词汇图鉴
14. 每日复习
15. 设置

所有页面必须适配手机和平板。

手机竖屏优先。

长文本需要自动滚动或者滚动容器。

正在朗读的台词应自动滚动到可视区域。

图片和文本都显示时，手机优先采用上下布局。

平板宽屏采用左右分栏。

要支持系统字体缩放。

## 7. 多角色 TTS 播放

使用 Android 系统自带 TextToSpeech。

每个角色允许配置：

- language
- preferredVoiceId
- rate
- pitch

默认：

- 英语语速：0.8
- 中文语速：1.2

支持在设置界面自由输入数值，并提供加减按钮。

必须允许用户先清空输入框，再输入新值。

校验非法输入，不能因空字符串导致程序崩溃。

功能：

- 朗读单词
- 朗读英语例句
- 朗读中文翻译
- 朗读完整剧情
- 多角色顺序朗读
- 当前句子高亮
- 当前句子的图片自动切换
- 自动播放下一句
- 单句重复
- 暂停
- 恢复
- 上一句
- 下一句
- 循环播放
- 可选只播放英语
- 可选英语加中文

必须通过 TTS 播放完成回调推进队列，不能根据字数推测朗读结束时间。

缺少指定音色时自动回退到可用音色。

当设备未安装可用的离线 TTS 语言包时，需要明确提示，并提供文字模式，不能直接崩溃。

## 8. 锁屏和后台朗读

当玩家进入纯故事听力模式时：

- 屏幕锁定后可以继续朗读
- 支持通知栏播放控制
- 支持耳机媒体按键
- 支持暂停与恢复
- 支持音频焦点管理
- 正确处理电话来电等音频中断

使用符合 Android 系统规范的前台媒体服务方案。

注意 Android TextToSpeech 与 Media3 音频播放器不是同一个接口。需要为 TTS 实现兼容的队列或在必要时将 TTS 合成为应用私有缓存音频，再用播放器播放。

不要声称只增加 MediaSessionService 就能自动完成 TTS 后台播放。

前台游戏时支持保持屏幕常亮，用户可关闭。

不要依赖 WakeLock 无限保持 CPU 活跃。

玩家锁屏期间遇到互动题目时，暂停朗读并等待玩家返回。

## 9. 学习与复习机制

词汇掌握度按照词条 ID 单独记录。

支持：

- 新词
- 学习中
- 复习中
- 已掌握
- 需要强化

实现间隔重复。

记录：

- wordId
- reviewCount
- correctCount
- wrongCount
- lastReviewedAt
- nextReviewAt
- masteryLevel
- retentionParameters

优先采用明确版本的成熟算法；如使用简化算法，必须编写单元测试和调度规则文档。

答错题自动加入复习池。

重复刷题的 XP 奖励逐渐减少。

案件星级与词汇掌握度分开。

## 10. 本地存档

使用 Room。

必须实现：

- 自动保存
- 退出后继续
- 章节进度恢复
- 案件完成状态
- 单词掌握度持久保存
- 证据状态持久保存
- 设置持久保存

内容资源与用户进度必须分离。

升级 APK 后不得覆盖用户存档。

Room Schema 变更必须提供正确的 Migration。

禁止使用破坏性迁移作为正式默认方案。

## 11. 图片和资源

所有图片使用本地 Assets。

优先支持 WebP。

现有例句图片直接复用。

剧情图片建议使用 16:9 或 21:9 横向图片，在竖屏下采取合适的裁剪方式。

支持：

- 图片预加载
- 内存缓存
- 低内存设备
- 缺图占位画面
- 缺图错误日志

不得在 APK 运行时尝试从网络加载尚未打包的图片。

如果剧情插画尚不存在，应提供明确的占位图和资源清单。

不要将占位图伪装成已经完成的正式画面。

## 15. 开发执行顺序

请按以下阶段实施。

Phase 1：
分析现有词汇仓库，建立 Kotlin Android 项目，完成 JSON 导入和本地图片加载。

Phase 2：
实现游戏主菜单、案件选择、数据驱动剧情播放器和原生 TTS。

Phase 3：
实现至少一种完整调查关卡，包括英语对话、单词题、线索收集、推理题、结案结果。

Phase 4：
扩展全部关卡组件，完成 Room 存档、词汇复习和游戏积分。

Phase 5：
实现多角色语音配置、纯听力模式、后台播放和大屏适配。

Phase 6：
完成 Case01 全部剧情资源、词汇覆盖验证、测试、CI 和 APK 构建。

每个阶段完成后均应保持项目能够编译运行。

不要只输出设计方案，要实际建立工程文件。

若仓库与开发环境可用，请直接开始实现，不需要对已经明确的技术选择反复提问。

对于需要外部资源的内容，使用本地占位实现并明确记录，不得声称未完成的部分已经完成。

最终报告必须列出：实际完成内容、未完成内容、测试结果、APK 文件路径，以及下一步建议。
